# config —— 用户数据：设置、账号、token

## 用途

程序所有可写数据都在这个目录里：全局设置、资源版本记录，以及账号数据
（每个角色一份 JSON，token 密文就存在账号文件里）。第一次运行时目录是空的，
程序会按需自动创建。

## 目录结构

```
config/
├── settings.json                全局设置（MAA 路径、上次账号等）
├── gamedata.json                资源版本记录（自动生成）
├── <昵称> <服务器>.json         ★ 每个角色一份账号配置（练度 + 缺卡 + token 密文）
├── _did.json / _removed/        本机随机设备指纹 / 删除账号的备份（自动生成）
├── gacha/                       抽卡记录缓存：<账号文件名>.json（只增不减，删了重新同步即可）
├── 作业站/                       导出「作业站本地导入」格式（API /api/export 生成，界面暂无入口）
├── subprof_cache.json           分支中文名缓存（边同步边学）
├── nav.json                     活动关导航的坐标覆盖（可选，手写；活动换版 UI 挪位置时用）
├── navtpl/                      老故事集的卡片模板（可选，MN.png 这种；缺了就自己截一张补）
├── train-plan.json              没做完的培养计划（材料不足暂停时自动生成，「继续培养」读它；做完即删）
└── tokens.json                  旧版密文 token 库：迁移产物 + 只读兜底，不再写入
```

### nav.json（活动关导航坐标）

MAA 进不去活动章节（模板图对不上当前 UI），所以这段由程序自己点，坐标是
1280×720 口径。默认值写在 `core/stagenav.py` 的 `DEFAULT_POINTS` 里；活动换版后
主题页的区域名位置会重排，那时写这个文件覆盖即可，不用改代码：

```json
{
  "activityCard": [187, 387],
  "themeZone": [1055, 399],
  "zoneRows": [[1125, 471], [1125, 565], [1125, 659]]
}
```

量法：进对应页面截一张图，取目标位置的像素坐标，x、y 各除以 1.5（1920×1080 时）。

#### zoneIcons：活动地图右下角的「分区图标」

活动地图右下角**不是**一个 EX 开关，而是**一排分区图标**（2~4 个）：基础关 /
EX / S / MO，点哪个切到哪个分区（选中的那个会亮）。EX 也不总在最右边——
DM 的「破败前线」、BB、MT 的「谒见神祇」、PV 的「彩车游行」都在中间。

哪一格是哪个分区不用猜：资源库的 `zoneId` 排序就是界面顺序（基础 → EX →
S/MO），`stagenav.zone_rows_of()` 从代号直接算出来（`DM-EX-1` → 1、
`DM-MO-1` → 2、`BB-S-1` → 2），所以只要给出**这一排图标的坐标**即可：

```json
{"zoneIcons": {
  "DM": [[923, 608], [1026, 608], [1143, 608]],
  "WD": [[1063, 608], [1191, 608]]
}}
```

下标 = 分区序号（0 基础 / 1 EX / 2 S 或 MO）。

量法（推荐用工具）：进活动地图截一张全屏图，然后

```
python tools/zone_calib.py 截图.png                # 列出候选峰 + 生成预览图
python tools/zone_calib.py 截图.png --pick 2,3,4 --name DM   # 选定后输出配置行
```

原理是图标为花纹密集的徽记、背景为平滑插画，逐列灰度标准差在图标处成峰；
纵坐标统一 950（1920 口径，徽记高约 110px，落在 900~1000 都能点中）。工具给的
数值可能偏几十像素（菱形徽记左右两个尖各出一个峰），**以预览图里竖线穿过徽记
中心为准**——图标宽约 120px，偏 30~50px 仍点得中。换成 1280 口径：x÷1.5、
y=(y-38)÷1.5（38 是窗口标题栏高度，截图带标题栏时）。

写好后跑 `python tools/smoketest/smoke_test.py`，B35 会检查图标数量、坐标
范围和左右间距。

内置已标定 35 个活动（2026-11-18 从真机截图分三批标定）：DM / WD / BB / GO /
GA / HE / MT / BI / RS / PV / MN / NL / HS / OR / CW / DV / MB，以及第三批的
SV / BP / EP / TW / LE / ZT / FC / EA / OF / RI / DH / IC / SL / AS / AT /
CB / CV / AD。没标定的活动：EX 退回老的单点 `exSwitch`，S / MO 会明确报错让你
补坐标——**别让它瞎点**。

其中 CW 只标了前 2 格（未来将至 / 过往未尽）：第 3 格「紧握当下」那套 UI 不是
常规战斗列表，MAA 跑不了 CW-S，标了反而会把它点开，所以故意留空并让
`goto_subzone` 报「只标了 2 个」。

第三批里有几种长得不一样的界面，都按「图标中心」量，下标含义不变：

| 界面长相 | 活动 | 说明 |
|---|---|---|
| 一排圆形/菱形徽记 | TW / ZT / DH / IC / SL / AS / AT | 一格一个分区，选中会亮 |
| 左边活动横牌 + 右边 EX | SV / BP / EP / EA / RI / AD / LE / FC | 横牌 = 基础区，也当一格点（归位用） |
| 「地区切换」小面板 | OF | 三个小方块 ①②EX，OF-F 在第 2 格 |
| 城区 / 区域选项卡 | CB / CV | 两个大页签，第 2 个是 EX 那批 |

#### zoneRowByCode：界面格数和资源库分区数对不上时硬指

`zone_rows_of()` 默认按资源库 `zoneId` 排序算「第几格」。有两个例外：

| 代号前缀 | 指到 | 为什么 |
|---|---|---|
| `SV-EX` | 1 | SV 复刻过，资源库里同时收着原版 `act10d5_zone1` 和复刻的 `act11sre_zone1`，同一活动排出 3 个 zone，EX 被算成第 3 格，界面上只有两格 |
| `IC-P` | 0 | IC-P-1 / IC-P-2 在资源库里自成一区（zone4 / zone5），界面上仍挂在基础区那张图里 |

```json
{"zoneRowByCode": {"SV-EX": 1, "IC-P": 0}}
```

前缀按**整段**匹配（`IC-P` 认 `IC-P-1`，不认 `IC-PX-1`）。

#### exSwitchByEvent：只有「基础区 + 一个 EX 按钮」的活动

不是所有活动都是整齐的格子。老活动的右下角是**左边一个 EX 按钮、右边一块活动名
/ 副标题**（WR 铁窗徽记、WB 小「EX」方块、IW 棕红「EX」条、GT 菱形「EX」），
没有可用的分区序号，硬按 `zoneIcons` 的下标点会点到副标题上。这类活动记单点：

```json
{"exSwitchByEvent": {"WR": [1073, 605], "WB": [1005, 628],
                     "IW": [1175, 620], "GT": [1171, 605]}}
```

`goto_subzone` 发现该活动没有 `zoneIcons` 时走单点分支：点一下 EX 按钮 →
隔 `MAP_DELAY` 截图比对画面变化，没变化就如实报「EX 按钮没反应」，不会假装成功。
这一类**不做「先归位再切」**（界面上根本没有基础格可归位）。

`exSwitch` / `exSwitchByEvent` 的默认值 `[1199, 620]` 是**没标定活动的最后兜底**
（历史上 EX 恰好在最右边的活动能蒙对），新活动请按上面的两种方式之一标定。

> `GT-HX-*` 与 `GT-EX-*` 在游戏里同属一个 EX 分区（资源库都是
> `act13d2_zone2`，界面上共用一个「EX」图标），所以代号统一归一成 `ex`：
> 分区下标、排序、预检的前置展开都按 EX 走。

`_storyskip.png`（剧情回放右上角「跳过▶」，字形掩码判剧情页用）和
`_wakeup.png`（登录页「开始唤醒」按钮，重启流程认登录页用）。

裁法：在 1920×1080 的网格页截图上，**只裁卡片正中间那块 200×165**——卡片本体
约 214×204，四周留一点边，左上角的进度徽章和「NEW!」角标都要切在外面（这两个
东西会变：进度会涨、NEW 会消失，带进来就会失配）。程序按屏幕宽度等比缩放，
换分辨率也不用重裁。

判断裁得对不对：拿这张图跑一次导航，真卡分数应该 **0~5**，无关卡 20 以上。
2026-11-17 46 张全部按「网格实测」流程重裁并逐个真机导航验证（每张在自己
来源屏 0 分命中、别的卡 ≥12 分才收）；之前按「卡片+周边背景」裁的 400×258
老图，玛莉娅·临光的分数是 999（完全认不出）。

**别用「滚到第几屏、第几个格子」这种写法**：新活动一上线，卡片会整体往下挤，
按位置找必然找错。模板匹配才是稳的。

新活动上线（网格里多了张新卡）：从网格截图裁一张 200×165 的卡片中心图，按
真前缀命名（进图读左上角关卡代号）放进 `backend/core/navtpl/` 重新打包，或在
`config/navtpl/` 放同名文件热生效，不需要改代码。

### navtpl/events/（当期活动的导航按钮）

当期活动（终端页活动提示条 → 活动地图 → 右下区域按钮那套，见
`docs/backend.md` 的「当期活动导航」）用的是同一套模板匹配，模板放
`config/navtpl/events/`（优先）或内置的 `backend/core/navtpl/events/`：

    _entry_track.png   终端页那条活动提示条下半截的黄钻石进度（共用，换活动不一定要重抠）
    TL_z1.png          活动地图上的基础区节点（残照终尽）
    TL_z2.png          关卡列表右下角的 EX 区按钮（长冬初青）
    TL_z3.png          关卡列表右下角的 S 区按钮（世纪之春）
    TL_mini.png        活动地图左上角的小游戏入口（战时新闻委员会）
    TL_shop.png        活动地图右上角的商店节点（炮火所掩埋的）

裁法和卡片模板一样：1920×1080 原图原样抠，把用户画的红框往里缩 6~8px，
别把红线抠进模板。文件名在 `backend/core/eventnav.py` 的 `ENTRIES` 里配，
新活动加一项即可（老的别删，复刻活动还能用）。

`tools` 那两张是「点进去不是关卡列表」的入口（小游戏 / 活动商店），由
`maatools` 里的同名功能消费（见 `docs/backend.md` 的「MAA 小工具」）。

这些文件都可以随时删除：删掉账号 `*.json` 只是丢失缓存，重新同步就回来了
（token 密文也在里面，删掉后需要重新粘贴一次 token）。

## settings.json

```jsonc
{
  "maaDir": "D:\\2.game\\MAA-ALL\\MAA-ARK\\MAA-v6.20.1-win-x64",
  "maaEndDir": "",
  "maaDirs": ["D:\\2.game\\MAA-ALL\\MAA-ARK\\MAA-v6.20.1-win-x64"],
  "autoStartMaa": true,
  "autoUpdatePack": true,
  "autoCheckAppUpdate": true,
  "acceptPrerelease": false,
  "lastAccount": "小卡拉帕鲁灰#6408 官服.json"
}
```

| 字段 | 说明 |
|---|---|
| `maaDir` | 全局默认 MAA 根目录（含 `MAA.exe` 与 `config/gui.new.json`）。写入路径时会自动规范化斜杠 |
| `maaEndDir` | 明日方舟终末地那一栏的 MAAEND 根目录。设置里按游戏分了 tab，两套路径互不覆盖；MAAEND 的任务链还没接，这项先留着位 |
| `maaDirs` | 用过的 MAA 根目录历史（添加账号时「已存过」列表的数据源） |
| `autoStartMaa` | 写完作业后是否自动启动 MAA |
| `autoUpdatePack` | 启动后是否自动下载新的游戏资源包（新关卡 / 新干员 / 新活动），默认开。关掉不影响使用，只是要等发新版才有新数据 |
| `autoCheckAppUpdate` | 启动后是否检查程序新版本，默认开。6 小时最多一次，且**只提醒不自动装**——下载与重启都要用户自己点 |
| `acceptPrerelease` | 是否接收 `vX.Y.Z-beta.N` 预发布版，默认关。关掉时预发布版本不会提示 |
| `lastAccount` | 上次选中的账号文件，下次启动直接恢复 |
| `emulatorPath` | 模拟器安装目录，**留空就用 MAA 配置里那个**（`ConnectSettings.Extras.<类型>.EmulatorPath`）。只有 MAA 里没配、或者想指另一个实例时才填 |
| `emulatorAutoStart` | 任务开跑前发现模拟器没启动，是否替用户启动，默认开（见 `docs/backend.md` 的「开跑前的环境闸」）。关掉后只提示不动手 |

这个文件可以直接手改；改完要重启程序生效（程序启动时读一次并缓存）。
删掉它等于恢复默认：引导会重新出现，需要再填一次 MAA 目录。
手改坏了 JSON 也不会丢数据：启动时会把坏文件改名成
`settings.json.broken-<时间戳>` 保住原件，程序按默认设置继续运行。

## schedule.json（定时任务）

设置 → 定时任务整页存在这个文件里，跟 `settings.json` 分开：任务列表改得频繁，
还要带运行记录，混进偏好设置里会让那份文件越来越难手改。

```jsonc
{
  "version": 1,
  "conflict": "stop",        // stop=停掉在跑的 / skip=跳过本次
  "onChainFail": "continue", // continue=继续后续 / stop=停掉整条链
  "tasks": [
    {
      "id": "s1a2b3c4",
      "enabled": true,
      "name": "早上挂长草",
      "mode": "time",        // time=按时间，chain=接在上一条后面
      "time": "08:00",
      "weekdays": [1, 2, 3, 4, 5, 6, 7],   // 1=周一 … 7=周日
      "program": "D:\\tools\\autostart-138.exe",
      "args": "--autostart --instance 138",
      "cwd": "",             // 空 = 程序所在目录
      "timeout": 0,          // 秒，0=不限
      "notify": true
    }
  ]
}
```

删掉这个文件等于清空全部定时任务；程序运行中读的是内存缓存，改完要重启或
在界面上再保存一次才生效。

## 账号文件（<昵称> <服务器>.json）

schemaVersion 2 快照（`backend/core/updater.py` 的 `build_snapshot`）加一段
`skd`。`maa` / `tags` / `note` / `skd` 是用户字段，重复同步不会被覆盖：

```jsonc
{
  "schemaVersion": 2,
  "account": { "uid": "…", "nickName": "…", "channelName": "官服", /* … */ },
  "maa":  { "dir": "D:\\…", "profile": "", "note": "" },  // 该账号绑定的 MAA 目录
  "skd":  { "alias": "大号",                               // 备注（添加时填的）
            "addedAt": "2026-11-05T07:40:00",              // 添加时间
            "data": "AQAAANCMnd8BFdERjHoAwE…" },           // base64(DPAPI(token))
  "tags": [], "note": "",
  "chars": [ /* 练度 */ ], "missing": [ /* 缺卡 */ ], "stats": { /* 统计 */ },
  "sync": { "syncedAt": "…", "source": "…" }
}
```

`maa.dir` 与 `skd` 同处一个账号文件：一个账号用哪个 MAA、拿哪个 token，
删文件即整体清除。从 MAA 导入干员识别结果（界面的「从 MAA 导入干员信息」）
也是改这份文件——只覆盖 `chars/stats/missing/sync`，其余原样保留。

### 终末地账号

同一个森空岛 token 若还绑了《明日方舟：终末地》角色，同步时会额外生成一份
账号文件（文件名 `<昵称> 终末地.json`），`account` 段多两个字段：

| 字段 | 说明 |
|---|---|
| `account.game` | `arknights`（缺省）或 `endfield`；界面按它区分账号、决定是否给「作业获取」 |
| `account.roleId` | 终末地角色 id（读取抽卡记录用的是 `account.uid`，不是这个） |

终末地账号没有 `chars/stats/missing`（终末地不吃 zonai 的 `player/info`），
只有身份 + `skd`，用途是抽卡统计（以及后续的签到）。

### token 加密（skd 段）

token 是账号凭证，明文落盘不放心，所以**每条 token 单独**用 **Windows DPAPI**
（数据保护 API，`CurrentUser` 作用域）加密后，以 base64 密文存进账号文件的
`skd.data` 段（备注与时间可见，token 是密文）。加密的性质来自 Windows 本身，
程序自己不保存密钥：

- **只能在本机、当前 Windows 用户**下解开；拷到别的电脑、或同机换用户登录，
  都会解密失败——换电脑迁移时别指望拷文件，到新机器上重新粘贴一次 token
  就行（界面「添加账号」）；
- 一个 token 绑定多个角色时，`skd` 会出现在每个角色的账号文件里；
  「同步全部」按明文 token 去重，不会重复同步；
- 单条解不开时只跳过该条并在启动日志里点名警告（换电脑后常见），
  不影响其他账号，也不会改名/删除任何文件。

管理 token 不需要手改文件：界面「添加账号」粘贴 token 同步成功后即落盘
（同步失败不落盘，向导里还能重试）；同一 token 重新同步以最新的为准。

### 旧版 tokens.json

`config/tokens.json` 是旧布局的全局密文 token 库（格式与 `skd` 段同构的
多条目列表），现在只作为迁移产物与只读兜底存在——「同步全部」会把它一并
读进来，但程序不再写入它。**所有账号都重新同步成功后，这个文件可以手动
删掉**；删掉任何账号文件前先确认 token 还在别处有备份。

## gamedata.json

程序自动生成的「资源版本记录」，用来判断内置游戏资源包有没有更新：

```jsonc
{
  "version": "2026.11.05",          // 上次见到的资源包版本
  "fingerprint": "3af97ae0",        // 上次见到的内容指纹
  "counts": { "chars": 469, "stages": 3647, ... },
  "acts": ["act55side", "act54side", ...],   // 上次见过的活动，用来算「新活动」
  "seenAt": "2026-11-05T01:50:00",
  "pending": null                   // 有更新时是一段 {from,to,delta,newActs}，用户点「知道了」后清空
}
```

- 删掉它 = 下次启动当作首次运行，静默重新记录，**不会弹更新提示**。
- 想再看一次更新提示（测试用）：把 `version` 或 `fingerprint` 改成别的值，重启即可。

## 旧版迁移

历史上有两代旧目录，升级后首次启动会自动压平（幂等，失败不丢数据）：

1. 更旧版数据在项目根 `skland/`（明文 `tokens.txt`）→ 先搬进 `config/skland/` 中转；
2. 旧布局 `config/skland/`（`tokens.json` + `accounts/…`）→ 压平进 `config/` 本层，
   路径里的第一级 `accounts/` 剥掉：`accounts/A.json → config/A.json`、
   `accounts/作业站/… → config/作业站/`、`accounts/_removed/… → config/_removed/`、
   顶层 `tokens.json` / `subprof_cache.json` → `config/` 同名。

安全规则：目标已有同名文件就跳过（宁可不搬也不覆盖）、单个文件搬失败留在
原地下次再试、自底向上只删真正搬空的目录——`config/skland` 只要还有东西
就整体保留。token 密文原样搬运（不解密不重加密）；明文 `tokens.txt` 的加密
转换仍延后到读取时做，转换成功后原文件改名 `tokens.txt.bak` 留底，读不了的
改名 `tokens.txt.broken` 留证。若 `tokens.txt` 与 `tokens.json` 并存（txt
不迁移、文件保留），里面的 token 不参与同步，启动警告会点名提示处理。

## 隐私

- `skd` 段与 `tokens.json` 是密文，但**不要**把它当作可以随便分享的东西——
  在能解密的那台电脑上它就等于明文 token；
- 账号 JSON 里有游戏 uid、昵称、完整干员练度，上传前注意（界面暂无
  「导出」入口：想分享练度先自行删掉 `skd` 段，或用 API `/api/export`
  导出只含练度的干净数据）；
- `.gitignore` 已忽略整个 `config/`，不会误提交。
