# frontend —— 界面层

## 用途

纯静态的界面代码，由 `backend/main.py` 起的本地 HTTP 服务托管（`http://127.0.0.1:<port>/`），
在 pywebview 的 WebView2 窗口里渲染。没有构建步骤、没有 npm、没有框架，改完刷新即可生效。

## 文件

| 文件 | 作用 |
|---|---|
| `index.html` | 页面骨架：左侧账号栏、中间主区（账号信息 + 模块菜单 + 模块面板）、右侧作业集 |
| `style.css` | 全部样式。深色玻璃拟态，颜色/圆角/字体集中在 `:root` 变量里 |
| `themes.css` | 内置浅色主题的变量覆盖 + 桌宠容器（第三方主题的样式在各自的包里，不在这里） |
| `app.js` | 全部交互逻辑，按功能分段注释 |

## 实现要点

**状态集中在一个对象**

```js
const S = {
  settings, accounts, current, detail,   // 当前账号与其完整配置
  maa, activities,                        // MAA 状态、快捷入口数据
  basket, result, searching,             // 作业集、最近一次搜索结果
  paths, pack, setup, gamedata, appInfo, // 路径、资源包信息、首启标记、资源版本、原生桥信息
};
```

没有响应式框架，所有 UI 都是「改 `S` → 调 `renderXxx()` 重画对应区块」。
区块之间互不依赖，错开重画不会互相清空。

**与后端的唯一通道**

```js
api('/api/xxx', body)   // 统一包成 {ok, data|error}
```

返回 `ok:false` 时抛错，调用处 `catch` 后 toast 提示。长任务（同步账号、写入 MAA）
走「创建任务 → 轮询 `/api/task?id=&since=`」，日志逐行推进弹窗的 `.log-box`。

**与桌面窗口的桥**

`window.pywebview.api` 提供三个原生能力（浏览器里打开时自动降级）：

| 方法 | 用途 |
|---|---|
| `choose_folder(title, initial)` | 设置页/引导页的「浏览」按钮，调系统文件夹选择框 |
| `open_folder(which)` | 打开 `accounts` / `config` / `logs` / `root` 目录（设置 → 数据与日志） |
| `app_info()` | 版本、是否打包、数据目录，用于设置页底部信息 |

`boot()` 里用 `waitPywebview()` 轮询等桥就绪，最多 2 秒；拿不到就当普通网页跑。

| `pollTask(tid, root, sel, onNew)` | 任务日志轮询（同步账号、写入 MAA、同步抽卡、签到、助手触发的后台任务共用）。日志容器默认 `#task-log`，签到面板两块日志各有 id，用 `sel` 指过去；第 4 参 `onNew(lines, kind, owners)` 给右栏分栏用（不传就只写弹窗）。承载日志的弹窗被关掉（`root.isConnected === false`）就停下——任务本身在后台跑，不需要前端继续问 |
| `setModule(mod)` | 模块菜单切换（作业获取 / 助手 / 抽卡统计 / 森空岛签到），同时决定右栏作业集要不要收起来 |
| `applyModuleAvailability()` | 按当前账号的游戏决定 tab 可见性：终末地账号**只留助手与抽卡统计**（隐藏「作业获取」和「森空岛签到」）并自动切过去；切回明日方舟时自动回作业获取（手动点过的模块不会被抢） |
| `renderGacha()` / `paintGacha()` / `paintGachaBody()` | 抽卡统计面板。统计卡常驻，下面是**视图三分**（`S.gachaView`）：按卡池 / 星级分布 / 抽卡记录；终末地的「角色寻访 / 武器申领」是另一层口径开关（`S.gachaTab`，右侧小分段按钮），与视图互不影响。按卡池是一池一张卡片（按最近抽卡时间倒序），池下挂这个池出的六星（最多 8 个：头像 + 名字 + 第几抽 + 时间 + new）。星级分布除星级条，还并列「实际出率 vs 官方公示」（方舟单抽 2/8/50/40%）与「六星出在第几抽」柱状图，底部是六星头像墙。抽卡记录一页 20 条（`S.gachaPage`），翻页控件带页码 + new 红点 + 「本页 N 个 new」 |
| `gachaSync()` | 「同步最新记录」：`POST /api/gacha/sync` → 轮询任务日志 → 重画面板 |
| `renderSignin()` | 签到面板：标题写当前账号，「单号签到」卡上写它的游戏 / 区服，全局卡上写「几个号有 token」；两个按钮按「有 token 且没有正在跑」置灰 |
| `signinRun(scope)` | 签到执行：`scope=all` 全部账号 / `one` 当前账号，`POST /api/signin/run` → 轮询任务日志写进各自那块 `.log-box.sign-log`。用 `S.signBusy` 挡并发（同 token 并发签到会被风控） |

**「全部加入」的两个入口**

结果列表右上角是「主按钮 + 倒三角」的组合：主按钮照旧是「每关要打的档」
（0-8/9 章普通+突袭、10-14 章只加磨难、15 章起只加险地，简单不加、某档没作业不降档），
倒三角里的选项**随结果集的关卡类型变**（`importOptions()`），选完按档一次导入，
不用加完再回作业集里一条条删：

| 结果集 | 倒三角选项 |
|---|---|
| 活动（TL / NL 这类） | 基础关卡与 TR · EX 关卡普通与突袭 · S 关卡普通与突袭 |
| 主线 0-9 章 | 普通关卡 · 突袭关卡 · 普通与突袭关卡 |
| 主线 10-14 章 | 简单难度 · 标准难度 · 磨难难度 |
| 主线 15 章+ | 险地难度 · 普通关卡 |

判定靠 stageId 前缀（`main_` / `easy_` / `tough_` 算主线，其余算活动）和代号里的
`-EX-n` / `-S-n`。**章节号要按结果集里第一个主线关算，不能直接看第一行**：搜章节号
（`2` / `12-`）时结果集里还夹着 S 支线关和 TR 教学关，第一行往往是 `TR-11` 这种，
按它判定会把主线误判成活动、菜单项全错。批量加入统一走 `addRows()`：每行取 best、
按「关卡 + 难度行」去重、已在作业集的跳过，然后 `renderBasket()` + toast「<档位>：加入 N 份」。

**`blocked`（打不了）的行不进批量导入**：一键导入的前提是「照着一份作业打一遍」，
打不了的塞进去只会白写进 MAA，所以 `addRows()` 直接跳过并报「跳过 N 关打不了的」。
逐行的「加入」按钮保持可用——那是用户自己挑的，加完可以自己拖顺序。

菜单是绝对定位浮层（`.add-split` + `.add-menu`，`z-index: 32`），
点别处或按 Esc 收起（文档级监听，因为结果区每次重绘都会换 DOM）。

结果列表的标题行（`.result-head`，含「全部加入」与倒三角）是 `position: sticky` 吸顶的：
`.results` 的上内边距挪进头部，滚动时头部停在列表顶边，底边用 12px 渐变把滚上来的
卡片虚化掉，不用滚回顶部就能批量导入。倒三角故意做得比主按钮字大一号（13.5px），
离远了也能看出是个下拉。

要求删掉了**：看着碍事。后端 `copilot.search` 仍然返回 `stories`，助手那边
`list_stages` 的 `note` 和终端的战报还用得到，只是不再渲染在结果区顶部。

搜到纯剧情代号（`TL-ST-1` / `EG-3`）时 `mode === 'story'`，结果区换成一张说明卡：
只有剧情、没有作业，首次观看送一颗源石。

**账号卡（`.hero`）的排版约束**

名字下面那行（区服 · 等级 · 看板 · uid）强制单行：`.hero-sub` 是 `nowrap + ellipsis`，
名字列 `.hero-id` 有 `min-width: 0`、`.hero-left` 是 `flex: 1 1 auto`——宽度不够时截断而不是折行
（折行会把整张卡撑高，把下面的模块菜单一起顶下去）。
右侧四个统计框 `.hero-stats` 是 `flex-wrap: nowrap`，`.stat` 不设 min-width、内边距 `4px 8px`，
四个总宽约 224px，窄窗口也不会折成 3+1。

**模块菜单**

账号卡下面那行是模块菜单，介于「账号信息」和「搜索框」之间：

| tab | 状态 |
|---|---|
| 作业获取 | 原有整块（搜索 + 结果），终末地账号不显示 |
| 助手 | 内置聊天助手（见下面「内置助手」一节）。跟游戏无关，终末地账号也显示 |
| 抽卡统计 | 读 `/api/gacha` 的本地缓存渲染，点「同步最新记录」才联网。头像走 `/api/avatar/<charId>`：`<img loading=lazy>`，加载失败自己移除，露出 `.op-av` 的首字母与星级渐变底（不需要前端判状态）。视图按账号留一份在 `S.gachaOf`，切账号 / 切菜单回来直接复用（不闪「读取中」）；切换侧栏分组时还原 `S.lastOfGame` 记下的上次那个号。已同步过但确实 0 条的号显示「这个账号没有抽卡记录」，不再劝人反复拉 |
| 森空岛签到 | 左右两块卡片：左「全局签到」一键签所有账号（方舟 + 终末地），右「单号签到」只签当前账号；各自一块日志，跑完底部给「成功 / 已签到 / 失败 / 跳过」汇总。终末地账号不显示这个 tab（签到本身支持终末地，全局里照样签） |
| ~~配置修改~~ | 这一版不做，tab 已删（不留占位） |

切换只改 `hidden` 与 `.app.no-basket`，不重建 DOM——搜索词与结果在切回来时
还在。抽卡统计不需要右栏作业集，`.app.no-basket` 把第三列收掉。
另外支持 `?mod=gacha` / `?mod=signin` 直接打开对应模块（做快捷方式用，与 `?q=TL-10` 同类）。
模块菜单整体比首版收了一圈（`padding 5px 11px`、`font-size 11.5px`、图标 13px），
并且 `align-self: flex-start` 按内容宽度排，不再拉满主区宽度——它只是切换器，别抢主区的视觉重量。

**快捷栏**

快捷栏只放活动，不再有 TR 之类的系列入口（要搜系列直接在搜索框输 `TR-`）。
每个胶囊是「活动名 + 关卡代号字母」，例如 `雪山降临1101 OS` / `时间啊，向前！ TL`。
顺序：**悖论模拟 → 复刻活动 → 其它进行中的活动**（按后端给的顺序），前端不再
按编号重排，否则一堆 NEW 会把当前活动挤出可视区：

- 复刻活动（后端 `activities[].reprint`）**钉在悖论模拟后面第二位**。资源库里
  它按原版开始时间算，早就排到十几条之外，前端先从列表里滤出来再插回去
  （`renderQuick` 里 `rerun` / `rest` 两个数组）。
- 复刻活动名字后面挂 `.chip-rerun`：`<b>复</b><b>刻</b>` 两个字两个颜色
  （粉 `#ffb3d9` / 蓝 `#9fdcff`），拼成一个小双色签（用户 2026-11-22 要求）。
- 字母由后端从关卡代号（OS-1…OS-S-5）里取，用户照着输 `OS-EX-1` 就能搜。

排序规则：`S.gamedata.pending.newActs` 里的活动带 `NEW` 角标；复刻之外的活动
只显示前 12 个（多了横向滚动）。

**资源更新提示**

`/api/bootstrap` 带回 `gamedata`（当前资源包版本 + 是否有待提示的更新）。
有 `pending` 时页面顶部出现提示条，列出新增干员/关卡数和新增活动；
点「知道了」调 `/api/gamedata/ack` 清掉，不点就每次启动都提醒。

**作业集拖动排序**

`renderBasket()` 渲染时给每项加 `draggable="true"`，`bindBasketDrag()` 做三件事：

1. `dragstart` 记下被拖的元素，加 `.dragging` 半透明样式；
2. `dragover` 时按鼠标在目标项的上半/下半，把被拖元素 `insertBefore` 到目标前/后
   —— 直接挪 DOM，不重排数组，拖动过程才不会中断；
3. `dragend` 调 `syncBasketOrder()`，按 DOM 顺序重排 `S.basket` 并重画（刷新序号）。

`S.basket` 的顺序就是 `/api/maa/apply` 里 `items` 的顺序，也就是 MAA 多作业列表里的执行顺序。

**首次引导的判定**

`/api/bootstrap` 返回 `setup.needsToken`（没有账号）与 `setup.needsMaa`（找不到 MAA.exe）。
`boot()` 在「没有账号」或「没填 MAA 目录」时弹引导；用户点「稍后设置」后本次会话不再弹。
首次引导与「添加账号」是同一个向导组件（`openAccountWizard`），只差标题文案与
「稍后设置」按钮：第 1 页选 MAA 根目录，第 2 页二选一（森空岛 token / 直接从选定的
MAA 导入建号），两种入口行为完全一致。

向导共用同一段 token 获取说明（`TOKEN_GUIDE` 常量）：
引导用户自己去森空岛社区登录后从 `zonai.skland.com` 的请求头里取 token，
**不放任何示例 token**（示例容易被当成可直接用的值抄走）。

## 内置助手（模块 tab）

模块菜单第二格 `data-mod="chat"` → `#mod-chat`，跟作业获取/抽卡统计/签到平级。

**为什么不做浮层**：早先是一个右下角圆气泡 + `position: fixed` 的 404×636 面板，
两个毛病——① 找它得先在角落里发现有这么个东西；② 它是固定定位，和设置弹窗抢
层级/位置，用户开着助手面板去配 Key 时，输入框和「保存」正好被面板压住。
改成普通模块后这两个问题都不存在，也不用写 `[hidden]` 的特殊覆盖。

- **铺满主区、左边缘对齐 tab 行**：`.chat-mod` 曾经写死 `max-width: 940px` +
  `align-self: center`，宽屏上左右各空一大块，卡片左边缘和上面的
  「作业获取 / 助手 / …」tab 行差 78px，看着像没对齐（2026-11-16 用户反馈）。
  现在卡片 `width: 100%` 铺满，头部/正文/输入区用同一套左右内边距（16px），
  三块边缘严格一致。文字本身另有 `max-width: 880px`，一行不会拉出半米长；
  用户气泡再留 3% 右余量，不贴着卡片右边框
- **进出即开关**：`setModule('chat')` → `enterChat()` 起轮询；切走 → `leaveChat()`
  停表。事件在服务端按 `since` 排队，切回来照样补齐，不需要后台空转
- **终末地账号也能用**：`setModule` 里只有 `gacha` 和 `chat` 豁免「终末地强制回

## 改样式

颜色、圆角、字体都在 `style.css` 顶部的 `:root`：

```css
--mint: #5eead4;   /* 主色（按钮、强调） */
--amber: #f5b955;  /* 警告 / 缺卡 */
--star: #ffcf6b;   /* 评分星 */
--panel: rgba(20, 24, 34, 0.72);
```

改完直接重启程序即可，静态资源是 `Cache-Control: no-store`，不会读到旧缓存。

**但别在这里写死颜色**（2026-11-25 起）：所有前景叠层、弹窗底色都必须走变量，
否则换主题时会出现「浅色界面里一块黑板」。见下一节。

## 主题系统（2026-11-25）

需求是「默认黑色，再加白色和卫戍协议主题，第三方主题包点下载才能用」。
做法分三层，**只有颜色是主题的事，布局和组件样式一律不跟着主题变**：

| 层 | 文件 | 作用 |
|---|---|---|
| 内置变量 | `style.css` 的 `:root` | dark 的默认值 |
| 内置浅色 | `themes.css` 的 `html[data-theme="light"]` | 只覆盖变量 |
| 第三方 | `config/themes/<id>/theme.css` | 按需下载，只覆盖变量 + 少量装饰 |

主题 id 挂在 `<html data-theme="...">` 上，切主题就是改这个属性 + 换一张
`<link id="theme-pack">`（内置主题把这张 link 删掉）。

**改造时踩过的坑，写下来免得再犯**：原来满篇 `rgba(255,255,255,.06)` 当加亮、
`rgba(13,16,24,.85)` 当压暗、`linear-gradient(165deg,#161b26,#0e121a)` 当弹窗底色。
浅色主题一上，这些全部原地不动 → 白主题里弹窗还是黑的。所以抽了三组变量：

```css
--tint: 255, 255, 255;   /* 「加亮」三元组，浅色主题翻成 17,24,39 就变成压暗 */
--shade: 13, 16, 24;     /* 「压暗」三元组 */
--panel-2 / --panel-3    /* 弹窗渐变的两端，别再写死 #161b26 */
```

用法：`background: rgba(var(--tint), .06)`。**新写样式请一律走这两个三元组**，
`rgba(255,255,255,…)` 只在 `:root` 里出现一次。

### 常规设置页（`SET_TABS` 第一项）

- **主题卡片**：`themeCards()` 生成，竖版卡片（缩略图 74px + 名称/说明 + 按钮）。
  内置两张永远 `installed: true`（少了它卡片会渲染成「下载」，点下去后端回
  「内置主题不能安装」）。未下载的第三方主题显示「下载（大小）」。
  缩略图**永远先垫一层色块**（`.theme-swatch.<id>`），`<img>` 盖在上面——
  远端预览图拉不到时只是露出主题渐变，不会白框/裂图。
- **先本地、再远端**：`loadThemes()` 第一次先打 `/api/themes?local=1`（只读盘，
  毫秒级）把卡片画出来，再拉全量补「可下载」。远端清单要联网、超时 6~8 秒，
  等它回来的话已装的第三方主题会短暂「消失」，用户以为主题丢了。
  任何一次清单落地都走 `markThemes()` + `paintThemeGrid()`，面板没开时
  `#theme-grid` 不存在，重绘自动跳过。
- **切换前先看可用性**：`switchTheme(id)` 里 `themeInfoOf(id)` 为空说明包没下
  或已被删，直接提示「先点卡片上的『下载』」，不要 `applyTheme` 悄悄退回深色
  （否则观感是「点了白色没反应」）。`themeCards()` 在「设置里的主题不可用」时
  把「使用中」标到深色上，避免一张卡都不亮。
- **`saveSettings()` 必须 `return d`**：调用方写的是
  `const d = await saveSettings(...)` 再读 `d.settings`，漏掉 return 就是
  `Cannot read properties of undefined`（2026-11-25 的「点白色报错」就是这个）。
  调用点还要用 `(d && d.settings) || S.settings` 兜一层。
- **显示主题桌宠**：`#theme-pet` + `#set-theme-pet`，只在主题声明了 `pet` 时出现，
  偏好存 `localStorage['maaprts.pet']`；关掉就整块不渲染（不是 `display:none`）。
- **开机时自动启动**：调 `POST /api/autostart`，默认关；失败要把勾选回滚。

两个调试用 query 参数（只影响这一次渲染，不落盘）：

```
/?theme=closure        预览某个主题，不改设置
/?open=settings        直接展开设置弹窗
```

配合无头 Edge 截图就是三套主题的回归办法：

```bash
msedge --headless=new --no-sandbox --user-data-dir=debug/edgeprof \
  --window-size=1500,950 --virtual-time-budget=6000 \
  --screenshot=debug/set-light.png "http://127.0.0.1:8788/?theme=light&open=settings"
```

`--virtual-time-budget` 别省：省了会截到 JS 还没填完的空壳（账号列全是「+ 添加账号」）。

### 桌宠（`syncThemePet`）

主题在 `theme.json` 里声明 `pet.video`（待机循环）、`pet.actions`（随机动作）、
`pet.every`（秒）与 `pet.float`。前端插一个 `<video>`：888×748 VP9-Alpha 透明
webm、fixed 右下、`pointer-events: none`、`object-position: bottom right`、
`max-height: 34vh`（34vh 是量出来的：再高就压住右栏底部那几行字了）。每
`pet.every` 秒换一个动作播一遍，`onended` 回到待机。窄屏和
`prefers-reduced-motion` 下直接不显示。

**点一下也播（2026-11-26）**：点击和定时共用 `playPetAction()`，连点就重播
（每次重新随机）；`play()` 起不来（素材坏 / 编码不支持）也回待机，不会停在
动作最后一帧。容器 `#theme-pet` 仍然 `pointer-events: none`，只给
`#theme-pet.on video` 放开点击——整块放开会把右下角那一片右栏按钮拦住。

## 助手页两栏与 markdown（2026-11-17）

`#mod-chat` 分两栏：`.chat-main`（左，聊天占大头）+ `.chat-side`（右 300px，执行日志）。
tool / tool_result 事件不再进聊天流，全部落到右栏 `#chat-side-log`（时间顺序、
自动跟随滚动、带「看进度」按钮）；reset / 清空按钮会把右栏一起清掉。

**右栏按账号分栏（2026-11-22 用户要求「日志随账号 tab 变」）**：`CHAT.side`
里按 taskId 存全部行（只存原文，归属渲染时现算，避免切号回填那一刻
`S.accounts` 还没到、把行全记到发起号头上）。`chatSideSwitch(file)` 在
`selectAccount` / `enterChat` 里调：先重画，再拉 `/api/tasks?file=` 把这个号
以前跑完的任务补进来。`paintSideLog()` 两级过滤——任务的 `owners` 不含当前
号就整块跳过，行再按 `sideOwnerOf()` 判（`[昵称]` → 那个号、`[组 …]` 与无前缀
汇总行 → 公共、认不出的前缀 → 跟着发起号）。「✓ 完成」这类前端合成行显式记
归属，否则会串成别的 tab 里一个孤零零的勾。`clearSideLog()` 只清当前账号
看得见的行，别的号留着。

markdown 渲染：`mdToHtml(src)`（app.js）——整篇先 `esc()` 再按行解析，无标签注入。
支持代码块、行内代码、标题、引用、有序/无序列表、粗体、斜体、删除线、链接、表格、
分隔线。`say` / `error` 消息走渲染，`user` 保持纯文本；流式更新按最新全文重渲。
星号等原样标记不会再漏给用户（用户反馈「不能显示那星号」）。

## 右栏改任务进度流（2026-11-17 晚）

用户反馈原方案不对：tool/tool_result 小字留在**左边聊天流**，右栏改放**后台任务的
进度日志**（即原来「看进度」弹窗里的内容）。实现：`chatNode` 的 tool_result 分支
拿到 taskId 后调 `sideTaskWatch(tid, name)`——往 `#chat-side-log` 追加一行任务头
（▶ 名称 · tid 前 8 位），再用 `pollTask(tid, document.body, '#chat-side-log')`
把日志流式写进右栏。`CHAT.sideTasks`（Set）挡住重渲染导致的重复跟踪；reset/清空
日志按钮会清右栏 DOM 但不清 Set（避免旧任务历史重灌）。多任务并发时日志按到达
顺序混排，靠任务头分隔。右栏标题改「任务进度」，空态文案「skill / 后台任务的
进度日志会显示在这里。」

**标题栏那个「停止」（2026-11-23）**：`.chat-side-head` 里 `#chat-side-stop`
（`.chat-head-btn`，`margin-left:auto` 贴右），点了只停**当前这个账号**——
`POST /api/run/stop {file}`，后端按账号筛实例/子进程。用户报的原话是「停止
不能指定，会一起停其他任务」，所以这个按钮永远只传 `CHAT.side.cur`，全停仍
走聊天（`stop_run` 不带 account）。结果用 `sideSay()` 写进右栏：右栏是数据
驱动的（按任务存行、按账号过滤），直接 append DOM 切一次账号就没了。
后端也不再「没给 file 就全停」：既没 `file` 也没 `all=true` 直接回错误
（`stopped=0`），免得 `CHAT.side.cur` 为空时一按把两台都砍了。
